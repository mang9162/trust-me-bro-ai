This matches the hard/soft component split in self-learn/self-report/SKILL.md's Tier definitions — use that file as the source of truth if a node's classification is unclear.

How to Read the 5 Edge Types

Every edge is labeled with its index number (0-69) so it can be referenced unambiguously in discussion.

Solid, numbered 0-12 — execution flow: the actual Stage dispatch sequence between workflow (wf) and Stage-1..6 (s1-s6). Numbers show real invoke/return order; "reject -> 1" is the Stage 6 alt-path when a scenario is rejected.
Light-blue dashed (13-18, 23-25, 27-30, 45-47, 49, 51, 54, 69) — cross-ref: one-way read. The source opens the target file for info (naming conventions, value lists, etc.). No key has to match.
Black dashed (19-22, 26, 48, 50, 53, 67) — bridge: a key/value produced by the source must match an entry in the target exactly (the ref column convention, Issue #2). Breaks if either side changes without the other.
Red dashed (31-42, 52, 57, 66) — trigger/notify: the source skill hands off to the target skill to do its own work (e.g. s1-s6 → generate-report to update the report, or s1-s6 → self-report when something self-learn-worthy is found). NOT a file reference — do not duplicate under References.
Solid green (43-44, 55-56, 68) — write: the source skill writes directly into the target file as part of its own procedure (self-report → tier JS, self-improve → log.js, execute-tdd → task status).

How to Use This When Writing or Editing a Skill

For any skill's node in this diagram, look at every edge leaving (or, for bridge/write, touching) its node:

  • Light-blue / black dashed (cross-ref / bridge) → one line each under ## References
  • Red dashed (trigger) → one line each under ## Trigger Skill — do not also add a ## References line for the same target
  • Solid green (write) → one line each under ## Writes To

See create-skill/SKILL.md for the exact section formats and the full connection-type checklist.

Keeping This Diagram in Sync (bridge with create-skill/SKILL.md)

This diagram's connection edges (cross-ref / bridge / trigger / write) and every skill's ## References / ## Trigger Skill / ## Writes To sections are a bridge pair — they must match exactly, in both directions:

  • Adding/removing/changing a line in a skill's References / Trigger Skill / Writes To → add/remove/relabel the matching connection edge here.
  • Adding/removing/relabeling a connection edge here → update the matching line in the source (and, for bridge/write edges, target) skill's file.

Execution-flow edges (solid, numbered 0-12) are not part of this bridge. They mirror the workflow orchestrator's dispatch order, so their counterpart is the explicit Stages / routing steps in workflow/SKILL.md — not a ## References / ## Trigger Skill / ## Writes To line. Change them together with those steps instead.

C2/C3 (data.md, gateway-directory.md, database-schema.md, etc.) reflect THIS project's actual context/tech-stack files. A project bootstrapped fresh via initialize may end up with a different concrete set of files — update this diagram (via self-learn) whenever such files are added, renamed, or removed, so it always reflects reality.

C7 (Work Output) is instantiated once per scenario — every scenario under work/Scenario/<FEATURE>/... has its own scenario.html / 01-Testdata/ / 02-Task/. The diagram shows one representative instance; its layout is owned by workflow/SKILL.md ## Layout.
