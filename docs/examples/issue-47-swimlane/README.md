## กติกาที่สคริปต์นี้ทำตาม

- lane เป็นแถบแนวนอน เรียงบนลงล่าง — บนสุด client ล่างสุด 3rd party เสมอ
- flow วิ่งซ้ายไปขวา ข้ามแถบขึ้นลงตามระบบที่รับผิดชอบ
- lane ตั้งชื่อเป็น service จริง เพื่ออ่านแถวเดียวรู้ว่าเทสต้อง mock ตัวไหน
- ข้อความในกล่องเป็นภาษาธุรกิจ ไม่มีชื่อ field / collection / function
- bracket ซ้ายจัดกลุ่ม lane (หน้าบ้าน / หลังบ้าน) ครอบด้วย `Business Condition`
- สี่เหลี่ยม = สิ่งที่ระบบทำ · ข้าวหลามตัด = เงื่อนไขที่แตกได้หลายทาง · วงกลมแดง = จุดจบของเส้นนั้น · เส้นประ = ไปถาม/บันทึกข้อมูล
- **แถบหนา = แยกทำพร้อมกัน (fork) / รวมกลับ (join)** — ต้องมี ไม่งั้นจะเผลอใช้ข้าวหลามตัดกับงานที่ทำพร้อมกันได้
  ตัวอย่างในรูป: บอทกดไลก์ ตอบใต้คอมเมนต์ และทักแชท **ทำครบทั้งสามในคราวเดียวได้** ไม่ใช่เลือกอย่างใดอย่างหนึ่ง
  เงื่อนไขว่าร้านตั้งอะไรไว้ แปะบนลูกศรแต่ละเส้นแทนการใส่ข้าวหลามตัด
- **ลูปต้องวาดเป็นลูปจริง** — มีวงกลมขาวเป็นจุดรวมทาง แล้วข้าวหลามตัด "ตรวจครบทุกคำสั่งแล้วไหม" วนกลับไปต้นลูปก่อนจะออก
  ตัวอย่างในรูป: ยิงคำสั่งไป Facebook เป็นชุดเดียว แต่ได้ผลกลับมาเป็นรายการ ระบบต้องไล่ตรวจทีละใบ
  ตอนแรกวาดเป็น "ทำให้ครบไหม" เช็คทีเดียวจบ ซึ่งผิด — และวางไว้ผิดเลนด้วย (Facebook แค่ส่งผลกลับ คนไล่ตรวจคือระบบเรา)

## กฎการเดินเส้นที่ต้องมี (เจ็บมาแล้ว)

**หนึ่งเส้น = จุดออกหนึ่งจุด → จุดเข้าหนึ่งจุด → หัวลูกศรหนึ่งหัว** ห้ามแฉก ห้ามใช้ช่วงทางร่วมกับเส้นอื่น
ถ้าตาเห็นเส้นเดียวแล้วเจอทางแยกกลางทาง = ผิด อ่านไม่ออกทันที

รอบแรกที่วาดพังเพราะลากทุกเส้นออกจากกึ่งกลางด้านขวาของกล่องเหมือนกันหมด ทำให้

- ข้าวหลามตัดแตก 3 ทาง แต่ออกจากมุมเดียวกัน แล้วค่อยแยก -> เห็นเป็นเส้นเดียวแฉก
- กล่องที่มีทั้งเส้นเข้าและออกทางด้านบน -> เส้นทับกันสนิท ตามไม่ได้ว่าเข้าหรือออก
- ข้าวหลามตัดมี 4 มุม แต่ถูกยัดให้รับ 5 เส้น (เข้า 2 ออก 3) -> ต้องมีมุมที่ใช้ร่วมกัน

สิ่งที่ต้องมีในเครื่องวาด

| กลไก | แก้ปัญหาอะไร |
|---|---|
| ระบุจุดเกาะได้เอง (`ay` / `by` ใน `right`) | เส้นหลายเส้นออกจากแถบ fork คนละความสูง ไม่ทับกัน |
| เข้าทางซ้ายได้ (`enter="left"` ใน `drop`) | กล่องที่มีเส้นออกทางด้านบนอยู่แล้ว ให้เส้นเข้ามาทางซ้ายแทน |
| จุดรวมทางก่อนเข้าลูป (`merge`) | ข้าวหลามตัดรับได้เข้า 1 ออก 3 พอดี 4 มุม เส้นวนกลับกับเส้นแรกมารวมที่จุดนี้ก่อน |
| สะพานข้ามเส้น (`hops` ใน `loopback`) | จุดตัดที่เลี่ยงไม่ได้ ต้องโค้งข้าม ไม่งั้นอ่านเป็นสี่แยก |
| ช่องเดินแยกของแต่ละเส้น (`corridor` / `lab_x`) | เงื่อนไขหลายด่านยิงลงจุดจบเดียวกัน ป้ายจะได้ไม่กองทับกัน |
| คุมจุดหักเส้น (`turn`) | ไม่ให้หักไปชนมุมกล่องที่ขวางอยู่กลางทาง |

## ส่วนที่ยังไม่ดีพอจะเป็นสกิล

สคริปต์นี้ **วางพิกัดเอง** — กล่องถูกอ้างด้วยเลขคอลัมน์ เช่น

```python
d_page = decision(4, ROW_MAIN, ["เพจเปิดใช้งาน", "อยู่ไหม"])
```

ถ้าจะแทรกด่านใหม่กลาง flow ต้องไปเลื่อนเลขของกล่องที่เหลือ และคนที่ไม่เขียนโค้ดแก้ไม่ได้
ตอนทำเป็นสกิลจริงน่าเปลี่ยนเป็น DSL แบบข้อความตามที่เสนอไว้ใน issue

ส่วนที่ใช้ซ้ำได้เลยคือ **กติกา layout** กับ **ฟังก์ชันวาดรูปทรง/ลูกศร**
(`task` `decision` `store` `actor` `endpoint` และ `right` `drop` `rise` `data` ที่เดินเส้นแบบตั้งฉากและแยกช่องไม่ให้ป้ายทับกัน)
