## กติกาที่สคริปต์นี้ทำตาม

- lane เป็นแถบแนวนอน เรียงบนลงล่าง — บนสุด client ล่างสุด 3rd party เสมอ
- flow วิ่งซ้ายไปขวา ข้ามแถบขึ้นลงตามระบบที่รับผิดชอบ
- lane ตั้งชื่อเป็น service จริง เพื่ออ่านแถวเดียวรู้ว่าเทสต้อง mock ตัวไหน
- ข้อความในกล่องเป็นภาษาธุรกิจ ไม่มีชื่อ field / collection / function
- bracket ซ้ายจัดกลุ่ม lane (หน้าบ้าน / หลังบ้าน) ครอบด้วย `Business Condition`
- สี่เหลี่ยม = สิ่งที่ระบบทำ · ข้าวหลามตัด = เงื่อนไขที่แตกได้หลายทาง · วงกลมแดง = จุดจบของเส้นนั้น · เส้นประ = ไปถาม/บันทึกข้อมูล
- **แถบหนา = แยกทำพร้อมกัน (fork) / รวมกลับ (join)** — ต้องมี ไม่งั้นจะเผลอใช้ข้าวหลามตัดกับงานที่ทำพร้อมกันได้
  ตัวอย่างในรูป: บอทกดไลก์ ตอบใต้คอมเมนต์ และทักแชท **ทำครบทั้งสามในคราวเดียวได้** ไม่ใช่เลือกอย่างใดอย่างหนึ่ง
  เงื่อนไขว่าร้านตั้งอะไรไว้ แปะบนลูกศรแต่ละเส้นแทนการใส่ข้าวหลามตัด
- **ลูปต้องวาดเป็นลูปจริง** — มีวงกลมขาวเป็นจุดรวมทาง แล้วข้าวหลามตัด "ตรวจครบทุกคำสั่งแล้วไหม" วนกลับไปต้นลูปก่อนจะออก
  ตัวอย่างในรูป: ยิงคำสั่งไป Facebook เป็นชุดเดียว แต่ได้ผลกลับมาเป็นรายการ ระบบต้องไล่ตรวจทีละใบ
  ตอนแรกวาดเป็น "ทำให้ครบไหม" เช็คทีเดียวจบ ซึ่งผิด — และวางไว้ผิดเลนด้วย (Facebook แค่ส่งผลกลับ คนไล่ตรวจคือระบบเรา)

## กฎการวาดที่ต้องมี (เจ็บมาแล้วทุกข้อ)

ตัวอย่างนี้ผ่านการรีวิวจากคนใช้จริงหลายรอบ ทุกข้อด้านล่างคือของที่ถูกตีกลับมาแล้วแก้

### 1. หนึ่งเส้น = จุดออกหนึ่งจุด -> จุดเข้าหนึ่งจุด -> หัวลูกศรหนึ่งหัว
ห้ามแฉก ห้ามใช้ช่วงทางร่วมกับเส้นอื่น ถ้าตาเห็นเส้นเดียวแล้วเจอทางแยกกลางทาง = ผิด อ่านไม่ออกทันที

รอบแรกพังเพราะลากทุกเส้นออกจากกึ่งกลางด้านขวาของกล่องเหมือนกันหมด ทำให้
- ข้าวหลามตัดแตกหลายทางแต่ออกจากมุมเดียวกัน แล้วค่อยแยก -> เห็นเป็นเส้นเดียวแฉก
- กล่องที่มีทั้งเส้นเข้าและออกทางด้านบน -> เส้นทับกันสนิท ตามไม่ได้ว่าเข้าหรือออก
- ข้าวหลามตัดมี 4 มุม แต่ถูกยัดให้รับ 5 เส้น -> ต้องมีมุมที่ใช้ร่วมกัน

### 2. ข้าวหลามตัด 1 กล่อง = 1 คำถามใช่/ไม่ใช่ แตกได้ 2 ทางเท่านั้น
ห้ามยัดหลายทางไว้ในกล่องเดียวแล้วตั้งชื่อลอย ๆ แบบ "ผลของคำสั่งนี้เป็นยังไง" — นั่นไม่ใช่คำถาม เลยไม่มีคำตอบให้อ่าน
ตัวอย่างนี้แตก 1 กล่องกำกวมออกเป็น 5 กล่อง กล่องละคำถาม

### 3. ชื่อกล่องต้องเป็นภาษาคน เอาเงื่อนไขจากโค้ดมาเขียน
ห้ามแปลศัพท์โค้ดมาดื้อ ๆ — "ข้ามเงียบ" ไม่มีใครเข้าใจ ต้องเป็น "ตอบรูปใต้ไลฟ์ไม่ได้ ปล่อยผ่าน ไม่ถือว่าล้มเหลว"
วิธีทำคือไปอ่าน if ในโค้ดจริง แล้วแปลงแต่ละเงื่อนไขเป็นคำถามใช่/ไม่ใช่

### 4. เส้นออกจากข้าวหลามตัด เขียว = ใช่ / แดง = ไม่ใช่
เป็นสีของคำตอบ ไม่ได้แปลว่าดีหรือแย่ (บางคำถามตอบ "ใช่" แล้วหยุด ก็ยังเป็นเส้นเขียว)

### 5. ลูปต้องวาดเป็นลูปจริง และต้องหาให้ครบทุกลูป
มีจุดรวมทางก่อนเข้าลูป แล้วข้าวหลามตัด "ครบแล้วไหม" วนกลับก่อนออก
ถ้าโค้ดวน for ห้ามวาดเป็นกล่องเดียวเช็คทีเดียวจบ

ตัวอย่างนี้มี **ลูปซ้อนกันสองชั้น** ซึ่งตอนแรกมองข้ามไปทั้งคู่
- **ลูปนอก** วนบอทของร้านทีละตัว (ร้านตั้งบอทได้หลายตัว คอมเมนต์เดียวจึงยิง Facebook ได้หลายรอบ)
- **ลูปใน** วนตรวจผลของแต่ละคำสั่งที่ส่งไปในชุดเดียว

วิธีหาคือไล่ดู `for` / `map` ในโค้ดให้ครบ แล้วถามว่าอะไรอยู่ในตัวลูปบ้าง —
ของตัวอย่างนี้ เกือบทั้งผังอยู่ในลูปนอก

### 6. ระยะห่างแถวต้องมากกว่าความสูงของรูปทรง
diamond สูง 84 แต่ตั้งระยะแถวไว้ 74 -> ทับกันตั้งแต่บรรทัดที่เขียน เปิดดูสักครั้งก็เจอ
**เรนเดอร์ดูทุกครั้งก่อนส่ง** อย่าเชื่อว่าโค้ดถูกแล้วภาพจะถูก

### กลไกที่เครื่องวาดต้องมี

| กลไก | แก้ปัญหาข้อไหน |
|---|---|
| ระบุจุดเกาะได้เอง (`ay` / `by`) | 1 — เส้นหลายเส้นออกจากแถบ fork คนละความสูง |
| เข้าทางซ้ายได้ (`enter="left"`) | 1 — กล่องที่มีเส้นออกทางด้านบนอยู่แล้ว |
| จุดรวมทางก่อนเข้าลูป (`merge`) | 1, 5 — ข้าวหลามตัดรับได้เข้า 1 ออก 3 พอดี 4 มุม |
| สะพานข้ามเส้น (`hops`) | 1 — จุดตัดที่เลี่ยงไม่ได้ ต้องโค้งข้าม ไม่งั้นอ่านเป็นสี่แยก |
| สีเส้นตามคำตอบ (`branch`) | 4 |
| ช่องเดินแยกของแต่ละเส้น (`corridor` / `lab_x`) | 1 — ป้ายจะได้ไม่กองทับกัน |
| คุมจุดหักเส้น (`turn`) | 1 — ไม่ให้หักไปชนมุมกล่องที่ขวางอยู่ |
